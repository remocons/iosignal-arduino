# ESP32-CAM 세션 카메라

ESP32-CAM 사진을 remocon.kr 카드 하나만 열 수 있게 보냅니다. 카드와 장치가 E2E 키로 서로 확인하고 X25519로 세션 키를 새로 정하므로, 나중에 E2E 키가 새어도 지난 사진은 풀리지 않습니다. 공식 타입 camera-session.1을 씁니다.

## 준비물

- 보드: ESP32-CAM (AI Thinker) (2026-11-19 ESP32-CAM에서 세션 시작(X25519 약 55ms), 사진 해독, 다른 수신기의 가져가기, 틀린 키 거부, 세션 만료 뒤 자동 갱신(시험용 15초 빌드)을 확인. remocon.kr 카드(로컬 개발 서버)에서 사진, '다른 브라우저' 표시와 '이 브라우저로 받기'를 확인. 2026-11-27 cam=0/1과 카메라 다시 시작을 넣은 판을 ESP32-CAM(MB 어댑터)에 올려 다시 접속, $state cam=1, 열린 카드가 0.1초 안에 세션을 다시 맺음을 확인(카메라 시작 실패 경로는 재현하지 않음). 같은 날 세션 반납·유지(46바이트 알림, 40초 무응답 시 세션 종료)를 넣은 판을 올려, 열린 카드가 15초마다 유지 신호를 보내 40초 넘게 세션이 유지됨을 확인(반납은 로컬 가짜 카메라와 remocon.kr 개발 서버로 확인).)
- 네트워크: Wi-Fi 2.4GHz 공유기
- 앱: https://remocon.kr 장치 카드 (camera-session.1)

## 사용 순서

1. 스케치를 업로드합니다. ESP32-CAM은 USB-TTL 어댑터로 올리고, 올릴 때만 GPIO0을 GND에 연결합니다. 같은 폴더의 E2ESession.h도 함께 올라갑니다. Crypto 라이브러리(rweather)가 필요합니다(IOSignal과 함께 설치됨).
2. USB로 연결해 https://arduino.iosignal.net/wifi/ (보드 설정)에서 Wi-Fi를 넣습니다(데스크톱 Chrome·Edge, 보드가 저장). 같은 페이지에서 다른 IOSignal 서버와 장치 키도 넣을 수 있습니다.
3. 같은 페이지의 스케치 설정 e2e_key에 키를 넣습니다. 꼭 필요합니다: 비어 있으면 사진을 보내지 않습니다. 보드가 저장하고 다시 보여 주지 않습니다.
4. 같은 공유기에 연결한 브라우저로 https://remocon.kr 을 열고, ESP32-CAM 카드에 같은 E2E 키를 넣습니다(그 브라우저에만 저장). 카드가 장치와 세션을 맺고 사진을 보여 줍니다.
5. 다른 브라우저에서 같은 카드를 열면 '다른 브라우저가 받고 있다'고 나옵니다. '이 브라우저로 받기'를 누르면 세션을 가져오고, 먼저 브라우저는 사진을 더 열지 못합니다.
6. 카드의 전송 스위치로 멈추거나 다시 보내고, 간격으로 사진 사이 시간을 바꿉니다.

## 시그널 절차

| 보내는 쪽 | 받는 쪽 | 태그 | 값 | 설명 |
| --- | --- | --- | --- | --- |
| 장치 | 서버 | `@$ui` | `t=camera-session.1` | 공식 타입 camera-session.1입니다. 앱이 세션으로 사진을 여는 화면을 그립니다. 서버에 보관됩니다. $name(보드 설정 name), #search·#notify는 esp32cam과 같습니다. |
| 장치 | 서버 | `@$state` | `on=1;interval=1000;session=0;cam=1` | 전송 중인지, 사진 간격(ms), 사진을 받는 카드가 있는지(session), 카메라가 시작되었는지(cam)입니다. cam=0이면 10초마다 카메라를 다시 시작해 봅니다(리셋 뒤 가끔 실패함). 서버에 보관됩니다. |
| 장치 | 앱 | `@e2e-challenge` | `[1][이유][nonce 16][holder 8] (바이너리)` | 세션을 맺을 때 서명할 nonce입니다. 접속할 때(이유 0, 누구나 답함), 요청에 답할 때(1), 세션이 10분 지났을 때(2, 세션을 가진 카드가 답함) 보냅니다. 틀린 키(3)와 늦은 hello(4)에는 그 hello를 보낸 카드를 holder 자리에 적어 답합니다. |
| 앱 | 장치 | `<cid>@e2e-hello` | `[1] 또는 [1][A 32][HMAC 32] (바이너리)` | 1바이트는 challenge 요청입니다. 65바이트는 카드의 X25519 공개키 A와 HMAC-SHA256(E2E 키, "e2e-hello" 1 nonce A)입니다. 장치는 키가 맞을 때만 받아들이고, 받아들이면 nonce를 바꿔 같은 hello를 다시 못 쓰게 합니다. |
| 장치 | 앱 | `@e2e-ready` | `[1][B 32][HMAC 32] (바이너리)` | 장치의 X25519 공개키 B와 HMAC(E2E 키, "e2e-ready" 1 nonce A B)입니다. 양쪽이 HKDF-SHA256(X25519 공유값, salt=E2E 키, info="iosignal-e2e-session/1" nonce A B)으로 같은 세션 키를 만듭니다. 비밀값은 메모리에서 한 번 쓰고 지웁니다. |
| 장치 | 앱 | `@image` | `JPEG (세션 키로 암호화, 바이너리)` | 세션이 있을 때만 간격마다 보냅니다. 세션 키(64자 hex)를 signal_e2e의 키로 씁니다. 평문 사진은 보내지 않습니다. 세션을 맺은 카드만 열 수 있습니다. |
| 앱 | 장치 | `<cid>@` | `off / on / interval=2000` | interval은 100~60000ms만 받고 보드에 저장합니다. 처리 뒤(거부해도) 상태를 보냅니다. |
| 카드 | 장치 | `<cid>@e2e-hello` | `[1][K\|R][holder 8][seq 4][HMAC 32]` | 세션을 가진 카드의 알림(46바이트, 세션 키로 서명). K는 15초마다 유지, R은 페이지를 닫거나 새로고침할 때 반납입니다. 장치는 반납을 받거나 40초 동안 유지가 없으면 세션을 끝내고 모든 카드에 시작 신호를 보냅니다. |

## 참고

- esp32cam과 같은 보드와 카메라 설정입니다. 다른 점은 사진을 E2E 키로 바로 암호화하지 않고, 카드마다 새로 정한 세션 키로 암호화한다는 것입니다.
- 보드의 NVS에서 E2E 키를 읽어 내고 지난 통신을 모두 녹화해 두어도, 세션 키를 만든 X25519 비밀값이 남아 있지 않아 지난 사진은 풀 수 없습니다(전방향 안전성). E2E 키를 아는 사람은 새 세션을 맺을 수는 있으므로, 키가 새면 보드와 카드의 키를 바꿉니다.
- 세션은 한 번에 카드 하나입니다. 재부팅, 서버 재접속, e2e_key 변경, 10분 경과로 세션이 끝나고, 카드가 알아서 새로 맺습니다. 세션이 없는 동안 장치는 사진을 보내지 않습니다.
- 장치는 challenge 요청을 0.3초에 한 번, 서명된 hello를 0.1초에 한 번까지만 처리합니다. 키 추측과 세션 빼앗기를 늦춥니다.
- 카드는 브라우저의 WebCrypto X25519가 필요합니다(최신 Chrome, Edge, Firefox, Safari). IOSignal Desktop과 안드로이드 앱은 아직 이 타입의 사진을 보여 주지 않습니다.
- 키 교환은 E2ESession.h에 있습니다. 같은 입력에서 Node(웹 브라우저와 같은 WebCrypto 계산)의 X25519·HMAC·HKDF와 같은 결과를 내는지 시험했습니다.
