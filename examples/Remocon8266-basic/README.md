# Remocon8266 basic (웹앱 제어와 OLED 상태)

웹앱(remocon.kr)에서 Remocon8266 보드의 출력 3개(내장 LED, OUT1, OUT2)를 3구 스위치로 제어하고, 바뀐 상태와 누가 바꿨는지를 OLED에 보여 줍니다. SW1~SW3은 보드에서 출력을 토글하고 SW4는 CID·IP·서버를 보여 줍니다.

## 준비물

- 보드: Remocon8266 보드 (D1 mini 기반) (폴더의 회로도 PDF 참고)
- 네트워크: Wi-Fi 2.4GHz 공유기
- 앱: https://remocon.kr 또는 IOSignal Desktop 장치 제어 화면 (3구 스위치 switch3.1)

## 배선

| 보드 핀 | 연결 | 비고 |
| --- | --- | --- |
| GPIO16 (D0) | SW1: s1(내장 LED) 토글 | 외부 풀업 |
| GPIO0 (D3) | SW2: s2(OUT1) 토글 | 내부 풀업 |
| GPIO14 (D5) | SW3: s3(OUT2) 토글 | 내부 풀업 |
| GPIO13 (D7) | SW4: 접속 정보 화면 | 내부 풀업 |
| GPIO4, GPIO5 | SSD1306 OLED (SDA, SCL) | I2C |
| GPIO15 (D8) | OUT1: LED, 네오픽셀, 서보 등 |  |
| GPIO12 (D6) | OUT2 |  |

## 사용 순서

1. Wi-Fi는 업로드한 뒤 USB로 연결해 https://arduino.iosignal.net/wifi/ (보드 설정)에서 넣습니다(데스크톱 Chrome·Edge, 보드가 저장). 같은 페이지에서 다른 IOSignal 서버(호스트:포트), 장치 키와 보드 설정도 넣을 수 있습니다. 스케치의 Wi-Fi 값에 실제 값을 쓰면 그 값이 부팅할 때마다 우선합니다.
2. 스케치를 업로드합니다. OLED 첫 줄에 CID가 나오고 LED, OUT1, OUT2 상자가 보입니다.
3. 같은 공유기에 연결한 브라우저로 https://remocon.kr 을 엽니다(이 페이지의 직접 해 보기에서도 됩니다).
4. Remocon8266 카드의 1번(LED), 2번(OUT1), 3번(OUT2) 스위치를 누르면 OLED 상자가 채워지고 아래 줄에 'app s2=1'처럼 표시됩니다.
5. 보드의 SW1~SW3을 누르면 출력이 바뀌고 앱 카드도 따라 바뀝니다('SW1 s1=1'). SW4는 CID, IP, 서버를 보여 줍니다.
6. remocon pub "<cid>@msg" "안녕하세요" 처럼 보낸 글은 OLED에 6초 동안 나옵니다.

## 시그널 절차

| 보내는 쪽 | 받는 쪽 | 태그 | 값 | 설명 |
| --- | --- | --- | --- | --- |
| 장치 | 서버 | `#search` | `구독` | 앱의 검색 요청을 받도록 구독합니다. |
| 장치 | 서버 | `@$name` | `Remocon8266:HOME` | 이름과 분류(첫 : 뒤)입니다. 서버에 보관됩니다. 분류는 앱이 장치를 묶어 보여 주는 탭 이름입니다. 이름과 분류 모두 보드 설정 name(이름:분류)으로 바꿉니다(바꾸면 바로 다시 보냄). 분류가 없으면 앱의 미분류 탭에 나옵니다. |
| 장치 | 서버 | `@$ui` | `t=switch3.1` | 공식 타입 switch3.1입니다(확장형: 첫 키가 t). 앱이 그 타입의 화면을 그립니다. 서버에 보관됩니다. |
| 장치 | 서버 | `@$state` | `s1=0;s2=0;s3=0` | 현재 상태입니다. 서버에 보관됩니다. |
| 장치 | 앱 | `#notify` | `<cid>` | 접속했음을 알립니다. |
| 앱 | 장치 | `#search` |  | 앱이 시작할 때, 1초 뒤, 이후 15초마다 보냅니다. |
| 장치 | 앱 | `#notify` | `<cid>` | 검색에 자기 CID로 답합니다. |
| 앱 | 서버 | `<cid>@$name, $ui, $state` | `구독` | 보관된 이름, 버튼(타입), 상태를 바로 받아 카드를 만듭니다. |
| 앱 | 장치 | `<cid>@` | `s2=1` | 앱의 스위치가 값을 지정하는 명령을 보냅니다. 장치가 받는 태그는 @입니다. |
| 장치 | 앱 | `@$state` | `s1=0;s2=1;s3=0` | 명령을 처리한 뒤 상태를 보냅니다. 앱의 대기 표시가 풀립니다. |
| 서버 | 앱 | `<cid>@$state` | `close` | 장치가 끊기면 서버가 보내고 카드가 사라집니다. |
| 앱 | 장치 | `<cid>@msg` | `문자열` | OLED에 6초 동안 표시합니다(한글 가능). 규칙 문서에 없는 예제 전용 명령입니다. |
| 장치 | 앱 | `@$state` | `s1=1;s2=1;s3=0` | 보드의 SW1~SW3으로 바꿔도 상태를 보내 앱 카드가 따라 바뀝니다. |

## 참고

- s1은 내장 LED, s2는 OUT1, s3은 OUT2입니다. 내장 LED는 active low라 값을 반전합니다.
- all=1·all=0(모두 켜기·끄기)도 받고 상태를 한 번 보냅니다.
- OLED 아래 줄은 마지막 변경과 출처입니다: app(웹앱·CLI 명령), SW1~SW3(보드 버튼).
- 예전 Remocon8266 예제의 출력 제어 부분입니다. bayo.tv 버튼은 Remocon8266-tv, 주변 장치 목록은 Remocon8266-scanner로 나눴습니다.
- 2026-11-17 Remocon8266 보드에서 확인: 원격 s2=1, s3=1, all=0, all=1, s1=0, @msg(한글), 알 수 없는 명령에 상태 응답.
- 2026-11-17 사용자가 OLED(CID, 출력 상자, 마지막 변경, @msg 한글 표시)와 SW1~SW4, 앱 카드 반영을 확인했습니다.
